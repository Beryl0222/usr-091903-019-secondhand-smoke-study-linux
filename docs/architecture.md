# 架构与关键设计决策

## 1. 身份与分析编号分库

`IdentityVault` 内部是两组表：

- **身份表**：`household_id → 姓名/联系方式/住址`、`member_id → 出生日期`；
- **分析表**：`analysis_id(A-000001) ↔ member_id` 的映射单表存放。

分析角色只能看到 `analysis_roster()`：分析编号、社区、性别、当前年龄段；
出生日期不输出，年龄段由系统按日期计算。映射解析
（`resolve_analysis_id`）仅限伦理/管理员，且每次解析追加审计。

通知场景下现场角色只通过 `household_contact_for_notification` 取联系
信息，与暴露数据完全隔离。

## 2. 同意、搬家、退出与政策的日期截断

所有区间统一为半开 `[start, end)`，精确到日。人天物化
（`ExposureStore.materialize`）对每个成员做四层区间相交：

1. 居住片段（搬家当日起计入新社区）；
2. 家庭同意区间（撤回/到期日起无人时）；
3. 成员退出日（退出日起无人时）；
4. 研究窗口；政策期不是“截断”而是按干预生效日给每个 person-day 打
   `pre/post` 标签。

人天行一旦物化即为只增快照。生命周期事件（同意、搬家、退出）应在
物化前确定；这保证冻结引用的行不会被追溯改写。

### 离线补传与行版本

某日先物化为缺测（`measured=False`），之后设备补传到了有效读数时，
重新物化会生成**取代版本**：新行带 `supersedes` 指向旧行，旧行带
`superseded_by` 并保留在 `_contrib_by_id` 中。旧冻结的输入索引仍指向
旧行 ID，新运行使用新行，两者可并存复核。

## 3. 传感器去重与校准失效

- 读数主键 `(serial, sample_start, sample_end)`。重复补传计入
  `duplicates` 且不覆盖原值；同窗口不同读数报 409 冲突要求人工核查。
- 校准是时间窗口，可撤销。读数在读取时实时重算校准状态：窗口外或
  校准已撤销 → `invalid`。**行永不删除**，`valid_only=True` 的口径
  才供正式估算使用。
- 数据质量来自部署计划：应有窗口数 = 部署天数 × (1440/间隔分钟)，
  缺测 = 应有 − 已收到（含失效）。开放部署按今天截断。

## 4. 估算：真实下降 vs 人口变化 vs 缺测

按地区（204 个全部出现在结果中，数据不足标记 `insufficient_data`）、
政策期、年龄段聚合实测人天：

- **段均值**：段内实测人天 PM2.5 算术均值；
- **粗均值**：全部实测人天均值 —— 年龄构成变化会混入；
- **直接标准化均值**：`Σ 标准人口权重_b × 段均值_b`，权重在冻结中
  逐字保存，两期用同一标准人口，构成变化被剥离；
- 当粗变化与标准化变化差异 ≥ 0.5 时标记 `composition_driven`；
- 不确定区间：段均值方差按权重合成标准误，自由度用
  Welch–Satterthwaite 近似，95% t 分位数用 Cornish–Fisher 展开；
  零方差时区间退化为点。
- 缺测不进均值，但 `person_days_total / person_days_measured` 与
  质量计数随冻结保存，避免把“没测到”误读为“下降”。

## 5. 冻结的不可变性

冻结记录包含方法规格、权重、窗口、204 地区逐期结果、质量汇总、输入
行索引（contribution/envday 的 ID 与值），并有两个哈希：

- `input_fingerprint`：进入估算的输入行集合 SHA-256；
- `content_hash`：整条冻结内容的 SHA-256，`verify` 可检测任何篡改。

审计日志本身也是哈希链（每条记录含前一条的指纹），`AuditLog.verify`
重放校验。

## 6. 隐私分层流向

```
分析人员  → 分析编号、聚合估计、冻结（无身份）
社区      → 社区/场所类型粒度，格子 <3 户或 <5 实测天即抑制
伦理      → 聚合总览 → 地区质量与编号 → 编号的同意/居住/退出
           → 凭书面风险理由开启身份（每步审计）
现场      → 联系方式与派发清单（无分析编号、无暴露值）
```

定向通知载荷只有联系信息 + 健康建议；同一家庭多成员去重为一个目标；
通知及其审计中不出现暴露数值或排名。
